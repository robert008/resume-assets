1. Server級 AI 移植專案｜Flutter SDK化

On-device AI、Flutter Plugin 化、iOS/Android 跨平台（C++/FFI）

運用技術：On-device AI／Flutter／iOS／Android／C++／FFI／ONNX Runtime／OpenCV

將原本在 Server AI辨識模組移植至flutter行動端，單張人臉運算約500毫秒體驗即時、不卡頓，並且封裝成 SDK，方便套用到任意fluter專案且無網也能辨識。

背景與目標

  • 主管希望能在無網的環境下也能使用臉部辨識功能，於是才有了這個將Server辨識AI移植到行動裝置的專案
  • 接手的時候原本的flutter工程師已經離職，從他的專案可以看到他試圖在flutter層引用 opencv 以及 onnxruntime框架想要直接在 flutter 層直接運算AI辨識
  • 在 flutter 層直接運算AI辨識運算的結果相當糟糕，且在無法使用 flutter 異步多工的狀況下，執行結果就是UI直接鎖死3~5秒鐘

我的角色

  • 團隊角色：影像辨識團隊由我與另一位Server(python)工程師共同負責
  • 由我主導：透過 AI 多次的資料搜查與確認，且與同事討論之後確定要使用 FFI 架構，由我同事完成 python 轉 C++的部分，剩下部分由我完成後續C++與flutter的介接

關鍵挑戰

  • 第一階段：成功使用FFI介面呼叫了C++程式
  • 第二階段：重新將專案建構成 flutter plugin 架構，且為了能讓外部可使用將C++程式碼封裝成動態庫
  • 第三階段：app應用端引用了 plugin 架構後遇到apple的巢狀式動態庫(Nested Dynamic Frameworks)問題，只好再將C++編譯成靜態庫，才能通過apple的程式碼檢驗
  • 總結：C++ 不是我的專長，尤其靜態庫的編譯/鏈結難度更是超出我的想像；但最後還是能打通最後關卡完成交付的任務

效能與成果

  • 直接透過FFI介面在C++運算回來的結果從5秒 > 約500毫秒
  • 解決flutter層級無法使用多工造成的畫面凍結的問題
  • 最終完成了 flutter plugin 架構，任意專案都可以方便引用，重複利用性高
  • C++ 封裝成靜態庫，提供公司外部使用也不擔心C++程式內容被看到
  • On-device AI 趨勢：無網路也能運算，且減少雲端運算 loading，歐美對於AI的法律規範已逐步成型

G4. flutter_yolo_open_kit

商用免費物件偵測 | YOLOX & PP-YOLOE+ | Flutter FFI Plugin

運用技術：Flutter／YOLOX／PP-YOLOE+／ONNX Runtime／FFI

使用 YOLOX 和 PP-YOLOE+ 模型的商用友善物件偵測套件。與其他需要授權費用的 Flutter YOLO 套件不同，此 SDK 完全免費供商業使用。

核心差異

其他 YOLO 套件
  • 需要商業授權
  • 按 App 或按席位計費
  • 有限的模型選擇
此 SDK
  • 100% 商用免費
  • Apache 2.0 授權
  • 多種模型尺寸 (S/M/L)
  • YOLOX + PP-YOLOE+ 支援

支援模型

  • PP-YOLOE+ S (30MB) - 最快，即時偵測
  • PP-YOLOE+ M (90MB) - 平衡效能
  • PP-YOLOE+ L (200MB) - 最準確
  • YOLOX-M (97MB) - 中型變體
  • YOLOX-L (207MB) - 大型變體
